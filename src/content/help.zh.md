# Cerne Code 能做什么

这是智能体可以使用的工具目录。每一轮对话中，模型都会根据请求自行决定调用哪个工具(或不调用)——下面"智能体何时决定使用"这一列直接来自每个工具在代码中自带的描述，因此它们准确反映了模型在选择前读到的内容。

## 始终可用(无论是否打开项目文件夹)

| 工具 | 作用 | 智能体何时决定使用 |
| --- | --- | --- |
| `web_search` | 搜索网络并返回最相关结果的标题/URL/摘要。默认并行聚合 DuckDuckGo + Brave + Mojeek，无需账号或安装,去除重复项并按来源间的一致性排序(可在设置→网页搜索中配置)。每次调用可接受一个或多个查询。 | 当缺少项目或模型训练数据中没有的信息时——比如某个库的最新版本、外部文档、新闻。智能体会自行决定一次调用发送多少个查询:直接的请求发一个,请求有多个角度或第一次搜索结果不够时发多个(不同措辞、同义词)。 |
| `web_fetch` | 获取指定 URL 并返回页面的可见文本,不含 HTML/脚本。 | 在 `web_search` 之后,用来读取整个来源而不是只依赖搜索结果的摘要片段。 |
| `load_skill` | 通过确切名称加载某个技能的完整内容,该名称来自对话开始时列出的目录。 | 当用户的请求与某个已注册技能的描述相匹配时(见下方技能部分)。 |
| `ask` | 暂停当前轮次,向用户询问具体问题,可提供多选选项和/或自由文本。 | 当只有用户能做决定时——在多种方案间选择、确认有风险的操作、消除请求的歧义——而不是自行假设并继续。谨慎使用,只有在没有这个回答智能体真的会卡住时才用。 |

## 仅在打开项目文件夹时可用

| 工具 | 作用 | 智能体何时决定使用 |
| --- | --- | --- |
| `read_file` | 读取项目中某个文件的内容(或会话中已授权的额外读取文件夹)。 | 需要在解释、编辑或引用之前先查看文件的真实内容时。 |
| `list_dir` | 列出某个目录下的文件和子文件夹。 | 在动手修改之前了解项目结构,或查找某个文件的位置。 |
| `grep` | 在文件内容中搜索一个模式(正则表达式)。 | 查找某段文本、符号或字符串在项目中出现的位置。 |
| `ast_grep` | 结构化代码搜索(按 AST 结构而非松散文本匹配)——`$VAR` 匹配任意节点,`$$$ARGS` 匹配零个或多个。 | 当搜索关注的是代码结构(函数调用、导入、声明)而非松散文本时,优先于 `grep` 使用。 |
| `run_command` | 在项目目录下运行一个 shell 命令。设置 `background=true` 时不等待命令结束(用于开发服务器、watch 模式)。 | 运行测试、构建、lint、项目脚本;`background=true` 专门用于故意保持运行的进程。 |
| `check_background_output` | 读取后台启动的命令的累计输出和状态,不会停止它。 | 查看已用 `run_command(background=true)` 启动的开发服务器或长时间进程的进度。 |
| `stop_background` | 停止一个后台命令(终止进程)。 | 确认某个服务已正常启动后,或在用新版本替换旧版本之前。 |
| `list_background` | 列出所有已知的后台命令,无论正在运行还是已结束。 | 在启动新的开发服务器之前,检查是否已有上一次会话遗留的进程在运行。 |
| `write_file` | 创建或覆盖一个文件。写入会先进入镜像的沙盒文件夹——用户需要在界面中接受该差异后才会应用到真实文件。 | 创建新文件,或替换已存在文件的全部内容。 |
| `edit_file` | 编辑已存在的文件,将某段文本的一次精确匹配替换为另一段。同样写入沙盒,需经过接受。 | 对已存在文件进行局部、精确的修改。 |
| `ast_edit` | 结构化重写:模式(与 `ast_grep` 语法相同)的每一处匹配都会被重写模板替换。 | 重构场景——重命名调用、修改导入——比 `edit_file` 更安全,因为它作用于结构而非精确文本。 |
| `task` | 将一个定义清晰的子任务委托给一个用完即弃的子智能体,该子智能体运行自己的工具循环,只返回最终报告。 | 需要多次工具调用、但中间过程对用户不重要、只关心结果的子任务(例如:"找出所有用到 X 的地方并总结它们的位置")。 |
| `verify_completion` | 触发一个独立的、持怀疑态度的验证者(不是智能体本身)用真实证据复核任务是否真的完成。它只有读取/执行类工具,绝不包含编辑类工具。 | 在复杂任务(涉及多个文件、从零构建的内容)宣布成功之前——不用于结果显然可验证的简单单次调用请求。 |

## MCP 工具(外部服务器)

在设置→MCP 服务器中配置的每个服务器,都会自动以 `mcp__{服务器}__{工具}` 的形式加入智能体的工具目录。智能体决定是否使用它们的方式与原生工具相同——依据 MCP 服务器自身暴露的描述。这里不列出固定表格,因为它们因安装环境而异,取决于你配置了哪些服务器。

## 技能(Skills)

技能是一个 `SKILL.md` 文件,包含智能体通过 `load_skill` 按需加载的指令,无需在每次对话中重新解释相同的流程。每个会话开始时,智能体只会收到每个可用技能的目录(名称+描述)——只有当智能体决定调用 `load_skill(名称)` 时,才会读取完整内容。在设置→技能中创建和编辑技能。

## 手动模式 vs 自动模式

每个会话都有一个执行模式,在composer中"+"按钮旁边的选择器中选择:

- **自动**(默认):每个工具都直接运行,不暂停。侧边任务列表中的"取消"按钮可随时中断整个轮次。
- **手动**:每次工具调用(`ask` 除外,它本身就是一次暂停)都会停止当前轮次,并在运行前请求明确批准——适合你想在每个操作发生前逐一审查,而不是事后才能取消的场景。
